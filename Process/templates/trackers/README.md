# Шаблоны багов под трекеры

Баг сначала оформляется по базовому шаблону [`../bug.md`](../bug.md) (файл в `test-runs/bugs/`), затем при переносе
в трекер - по шаблону трекера из этой папки. Содержание то же; меняются разметка, разбиение на поля и способ
заполнения полей трекера.

| Папка | Трекер | Статус |
|---|---|---|
| [`youtrack/`](youtrack/) | YouTrack | готов |
| `jira/` | Jira | _когда понадобится_ |

## Выбор трекера

Тип и адрес трекера выбирает тот, кто запускает прогон:

- в `postman/.local/tracker.yaml` (не в git, у каждого свой):
  ```yaml
  type: youtrack                        # имя папки здесь
  url: https://youtrack.example.ru      # адрес трекера
  project: SH                           # ключ проекта
  ```
- или ключами `run.py --tracker youtrack --tracker-url <адрес> --tracker-project <ключ>` (перекрывают файл).

Выбор записывается в отчёт прогона (строка «Трекер»). Не задан - баги оформляются только по базовому шаблону,
перенос в трекер - после того как пользователь назовёт трекер.

## Новый трекер

1. Папка `<трекер>/` с `bug.md` (заголовок, описание в разметке трекера, поля) и `fields.yaml` (соответствие
   полей базового шаблона полям трекера).
2. Строка в таблице выше; `type` в `tracker.yaml` = имя папки.
3. Названия полей и значений сверить с конкретным экземпляром трекера (они настраиваются в каждом проекте).
