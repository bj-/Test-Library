# Security profile selection policy (Stage 3)

## Профили

Профили выбирают проверки по run tags, ограничению приоритета и детерминированности. Текущий `select_checks.py` включает проверку, если совпал хотя бы один `include_tag`, нет совпадения с `exclude_tags`, а приоритет не ниже заданного порога. Поэтому run tags нужно назначать осознанно; тег `security` сам по себе не означает включение во все профили.

| Профиль | Security inclusion | Обязательный состав | Ограничения |
|---|---|---|---|
| Smoke | `smoke` | только быстрые детерминированные P0 проверки критического пути: missing/expired auth, cross-owner read, cross-tenant read — если эти политики применимы | не включать полный перебор ролей, bulk, cache, async; максимум 40 checks, max P1 |
| CI | `ci` и/или `security` (по текущим include_tags) | детерминированные P0/P1: AuthN missing, expired token, базовые AuthZ, owner/tenant denial, role/scope denial, отсутствие побочных эффектов | быстрые изолированные тестовые данные; max P2, max 300 |
| Regression | `regression` | полная применимая матрица: позитивные/негативные пары, ownership read/write/delete, tenant list/search/create, roles/scopes, token lifecycle, alternate methods, bulk/nested/export | допускает более широкие комбинации; без лимита числа проверок |
| Release | `release` и/или `security` (по текущим include_tags) | все применимые P0/P1 security checks, критические межпользовательские/межтенантные границы, expiry/revocation, escalation, состояние после отказа | детерминированный gate; расширенный объём, но не флейковые/неизолированные сценарии |

## Правила присвоения run tags

- `smoke`: только если проверка P0/P1, детерминированная, быстрая, критична для безопасности и не требует тяжёлого окружения.
- `ci`: детерминированная, воспроизводимая проверка высокой ценности; test identities/data можно создавать и очищать автоматически.
- `regression`: основной tag для каждого применимого security-инварианта, если он не является заведомо дорогим/нестабильным.
- `release`: P0/P1, риск межпользовательской/межтенантной утечки, эскалации привилегий, token lifecycle или нарушение требований безопасности релиза.
- `nightly`: дорогие комбинации, широкие role×scope×tenant наборы, кэш, асинхронные jobs, нагрузочные или длительные propagation-window проверки. Не использовать nightly как замену критическим gate-проверкам.
- `pr`: только быстрые детерминированные проверки, способные дать сигнал до merge; учитывать текущую политику профиля PR.

## Правила выбора набора

1. Сначала применимость по API-контракту и policy model; только затем профиль.
2. При неизвестной policy не выбирать статус-код догадкой: `needs_clarification`.
3. Все применимые P0 checks включать в CI и Release; Smoke — только критические и быстрые.
4. Проверка не считается покрытой лишь потому, что в набор попал общий AuthZ тест: измерять coverage по измерению матрицы и типу операции.
5. Не объединять read/write/delete в один coverage item, если права или side effects различаются.
6. Для каждой негативной проверки по возможности добавить разрешённый контрольный путь.
7. Отчёт профиля должен содержать `applicable`, `selected`, `excluded_by_profile`, `needs_clarification`, а также причины исключения.

## Измеримые метрики

- **Applicable matrix coverage** = применимые покрытые клетки / все применимые клетки × 100%.
- **Risk-weighted coverage** = сумма весов покрытых применимых клеток / сумма весов всех применимых клеток × 100%; веса: P0=8, P1=4, P2=2, P3=1.
- **Boundary coverage**: число проверенных границ ownership/tenant/role/token lifecycle / число применимых границ.
- **Operation coverage**: число security-sensitive operations с AuthN+AuthZ+state assertions / число всех security-sensitive operations.
- **Negative side-effect coverage**: число запрещённых мутаций с проверкой состояния после запроса / число применимых запрещённых мутаций.
- **Unknown policy debt**: число клеток `needs_clarification`; публиковать отдельно, не включать в знаменатель покрытых клеток, но не скрывать из отчёта.
- **Profile gap**: число применимых P0 клеток, отсутствующих в обязательном профиле (целевое значение CI/Release = 0).
