# 0014. Записи стоп-тем (sg-restricted) - генерация только в дочерних сессиях, оркестратор «вслепую»

- **Статус:** принято (дополняет [0008](0008-ai-restricted-isolation.md), п. 4)
- **Дата:** 2026-10-29
- **Участники:** bj, Claude

## Контекст

По ADR 0008 тесты по записям с `automation.ai_generation.restricted` - только заготовки `[DRAFT]`, сценарии ассистент
не дописывает: основная сессия останавливалась фильтром уже при чтении подробностей. Защитное покрытие этих записей было
ручным.

Эксперимент 2026-10-28/29 (BFF-Mobile, решение bj 2026-10-28; ход - `docs/STATUS.md` проекта bff-tests): 8 записей
`sg-restricted`, по одной на дочернюю сессию `claude-opus-4-8` с пакетом контекста. Отказов фильтра - 0 (sonnet/haiku не
понадобились); 5 записей обоснованно признаны неприменимыми к модулю, 2 собраны частично, 1 - заготовка (мешали заглушка
core и нет TD, а не фильтр). Оркестратор (основная сессия, модель с фильтром) работал по номерам строк: файл
соответствия «пункт -> запись, ручки» не открывал, строки запуска по нему составила дочерняя сессия, результат проверялся
скриптами. Остановок основной сессии - 0.

## Решение

1. Группа `sg-restricted` - исполнитель `child` (`Api/taxonomy/security-groups.yaml`), а не `human`. Запись -
   **одна дочерняя сессия** `claude -p --model <executors.child.model>` с пакетом группы (`child_pack.py --records`).
   Отказ - та же запись на следующей модели лестницы (сейчас `claude-opus-4-8` -> `claude-sonnet-4-6` ->
   `claude-haiku-4-5`), затем - `external` или заготовка `[DRAFT]` для человека. Модель дочерней сессии сверять по
   `modelUsage`, не по ключу `--model`.
2. **Основная сессия - оркестратор «вслепую»:** порядок записей и ручки - в служебном файле `*.restricted.*` (закрыт
   `.claude/settings.json`), строки запуска по нему составляет дочерняя сессия; основная не читает пакеты, спецификации
   записей и текст тестов. Проверка - скриптами без содержимого (`Process/security-groups.md`, «Проверка после этапа
   исполнителя `child`»: генерация, lint, `meta`, `security_groups.py check`, число тестов). Итог дочерней - по
   нейтральным полям (вердикт, число тестов); при сомнении - разделы итога «что не применимо / ждёт решения».
3. Неприменимость записи дочерняя сессия обосновывает в docstring файла спецификации (пустой `tests()`), решение -
   за человеком в обзоре STATUS.
4. Прочее по ADR 0008 в силе: каталоги `restricted/` закрыты и для дочерних сессий; значения атак - только `{{TD-…}}`
   (ADR 0009); генератор по-прежнему ставит `[DRAFT]` тестам записей с флагом - до разбора человеком прогона;
   баги - `AI-доступ: restricted`; разбор прогона `groups/sg-restricted/` - человек.

## Альтернативы

- Оставить только `[DRAFT]` для ручного теста (ADR 0008 как есть) - покрытие остаётся ручным, хотя эксперимент показал,
  что дочерние сессии собирают такие тесты без остановок.
- Основная сессия генерирует сама - останавливается фильтром (2026-10-19, 2026-10-28).
- Специфика задач в контексте оркестратора - промпт оркестратора блокировался (2026-10-28), поэтому «вслепую».

## Последствия

- Записи стоп-тем автоматизируются; ручной долг - только то, что дочерние сессии не собрали или признали частичным.
- Модель с низким фильтром со временем выведут - правится `executors.child.model`; лестница - перебор моделей Claude,
  затем `external`.
- Оркестратор не оценивает суть тестов - качество проверяет разбор прогона человеком (`[DRAFT]` до разбора).
- Неприменимость - мнение модели: человек просматривает обоснования (пример 2026-10-29 - SSTI признана неприменимой,
  bj решил иначе: проверка через почту, `Process/collections.md` §4 «Тесты с доступом к инфраструктуре»).
