## Выводы

1. **Копать глубже** (порог `sessions.md` — больше 6 идей на 100 собранных): **kong** и **postgrest** — увеличить
   `max_items` и взять ещё пачки. Следом — **kubernetes** и **hasura** (5–5,5): стоит одна-две дополнительные пачки.
2. **GHSA (maven, go, rubygems, composer)** дают мало новых идей (2–4 на 100), но много пруфов (70–89 на 100): ценность —
   подтверждение существующих записей реальными CVE. Дальше — только если нужны пруфы для слабых категорий;
   **ghsa-nuget** (0,7) — остановить.
3. **strapi** (0,4) и **directus** (2,4) для API почти исчерпаны, но дали больше всего идей UI/DB (27 и 39) — кандидаты для
   выгрузки UI-багов (идея в `docs/ideas.md`, 2026-10-15), а не для API.
4. **apollo-server** — выборка мала (46 собранных); при доле API 33 % отдача 4,3 — можно добрать одну пачку.
   **supabase-auth** — фильтр пропускает лишь 21 из 120 (17 %), отдача низкая — не продолжать.
5. **Не начаты:** ghsa-pip, graphql-js, grpc-go, grpc-java, grpc-node, grpc-gateway. Пруфами слабее всего покрыты
   категории gRPC (`grpc-contract` 11,8 %, `grpc-errors` 18,8 %), `concurrency` (25 %), `business-logic` (35 %) —
   gRPC-источники нужны в первую очередь.
