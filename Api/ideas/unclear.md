# Спорные и непонятные идеи тестов

Сюда попадают идеи, у которых видно здравое зерно, но непонятно, что именно и как проверять: механизм не ясен,
данных мало, ожидание не сформулировать. Отказывать в них жалко, брать в inbox как есть — рано (решение bj,
2026-11-05, по сверке калибровки kong — `mining/nofix-calibration-kong.md`).

Как работает:

- Пишет внутренняя сессия (из сверок, шага 6, разбора inbox) и переносит сюда идеи с пометкой `?` из
  `build/mining/<id>/ideas.md` — сессии сбора `ideas/` не трогают (`mining/sessions.md`).
- Набралось 15–20 строк со статусом `open` — пакет для коллективного разбора другими LLM (ChatGPT, Gemini, Qwen):
  «сформулируй проверку — что делаем, что ожидаем, почему — или обоснуй отказ». Пакет — `reviewcheck.py` (ключ для
  этого файла добавить при первом пакете), ответы — рядом, `unclear.answer-N.md`.
- Ответы сводятся: идея сложилась — в `inbox.md` (статус здесь — `→ inbox #N`); не сложилась ни у одной модели —
  `reject` с причиной; мнения разошлись — решение bj.
