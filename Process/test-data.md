# Тестовые значения по ссылке: сессия сбора и сессия словаря

Решение — `docs/decisions/0009-test-data-by-reference.md`, формат словаря — `Api/test-data/README.md`, скрипт —
`Api/tools/test_data.py` (печатает только ID и счётчики). Смысл: ассистент, который генерирует тесты и разбирает
прогоны, видит описание проверки и ID значения, но не само значение. Значения из записей переносятся в словарь
двумя отдельными сессиями — сбор и словарь не встречаются в одном контексте.

```
сессия сбора (Test-Library)          сессия словаря (Api/test-data)          генерация, прогон, баги
записи: значение -> ID  ── inbox/ ──▶ ingest, проверка, наборы ── dict/ ──▶  {{TD-…}} в запросе, [TD-…] в результатах
```

## 0. Проверка изоляции (раз на машину)

1. Сессия в `C:\Git\Test-Library`: попросить прочитать `Api/test-data/README.md` — читается; прочитать любой файл
   `Api/test-data/dict/` или `inbox/` — **отказ** по запрету `.claude/settings.json`.
2. Сессия в `C:\Git\Test-Library\Api\test-data`: прочитать `dict/.gitkeep` — **читается**; прочитать
   `Api/checks/security/injection.yaml` — отказ.
3. Если в п. 2 чтение словаря запрещено (Claude Code применил настройки Test-Library) — сессию словаря открывать
   из клона в другом каталоге или на другой модели (раздел 3); записать результат в журнал `docs/STATUS.md`.

Проверено 2026-10-21 (Claude Code 2.1.306, дочерние сессии `claude -p`): п. 1 и п. 2 — как ожидается. Особенности
настроек: запись закрывают правила `Edit(...)` (правила `Write(...)` не действуют), поэтому для `inbox/` закрыто только
чтение; запреты сессии словаря на каталоги выше неё — только абсолютными путями `//c/Git/Test-Library/...`
(шаблон `**/...` считается от каталога сессии). Клон Test-Library в другом месте — поправить пути в
`Api/test-data/.claude/settings.json`.

## 1. Сессия сбора

Открыть в `C:\Git\Test-Library`. Одна тема за сессию (очередь — ниже). Промпт:

> Сессия сбора тестовых значений по ADR 0009 (`Process/test-data.md`, раздел 1). Тема: **<записи или файл>**.
> Для каждой записи найди в description, preconditions, steps, expected **конкретные значения для подстановки в
> запрос**: строки-нагрузки, наборы строк, готовые токены и заголовки, адреса и пути. Не значения: названия техник
> и уязвимостей, имена полей, коды ответов, описания поведения — их не трогать, формулировки не менять.
> 1. `python Api/tools/test_data.py next-id <КЛАСС> <N>` — зарезервировать ID (класс — короткий: SQLI, XSS, PATH,
>    SSRF, JWT, CMD, TPL, XXE…). Несколько значений одной цели — один набор `TDS-<КЛАСС>-<ЦЕЛЬ>`.
> 2. Записать **один новый файл** `Api/test-data/inbox/<ГГГГ-ММ-ДД>-<тема>.yaml` (формат — `Api/test-data/README.md`):
>    id, value (как в записи, без правок), encoding, set, title (нейтральное назначение без значения), records,
>    source: library. Файл не перечитывать (чтение inbox закрыто) и значения в ответе не повторять.
> 3. В записи заменить значение на ссылку: «значение `TD-SQLI-0001`» / «значения набора `TDS-SQLI-BASIC`»;
>    в запись добавить `test_data: [ID или набор, ...]`. Остальной текст не менять.
> 4. `python Api/tools/validate_library.py`, `python Api/tools/test_data.py check` (новые ID — «нет в словаре»
>    до сессии словаря, это норма).
> 5. Коммит: записи + файл inbox (`git add` по путям, без `git diff` по inbox), сообщение
>    «Тестовые значения: <тема> -> inbox (N значений)». Ответ — только ID, записи и счётчики.

**Очередь тем:** INJ-SQL, INJ-REFLECTED-XSS (пилот) → остальные INJ-* (`checks/security/injection.yaml`) → SSRF
(INJ-SSRF-PARAMETERS, REST-SSRF-URL-FETCH, ASYNC-WEBHOOK-URL-SSRF) → токены (AUTH-JWT-*, SEC-TOKEN-SIGNATURE) →
файлы (FILE-*, INJ-PATH-TRAVERSAL) → GraphQL. Записи с `automation.ai_generation.restricted` — не трогать (ADR 0008).
Найти оставшиеся значения: `python Api/tools/test_data.py check` и поиск по нейтральным признакам — печатать
только ID записей.

## 2. Сессия словаря

Открыть в `C:\Git\Test-Library\Api\test-data` (правила — `Api/test-data/CLAUDE.md`). Промпт:

> Сессия словаря по ADR 0009 (`Process/test-data.md`, раздел 2). Работаешь только со словарём этого каталога.
> 1. `git pull --rebase`, затем `python ../tools/test_data.py ingest`. Ошибки — исправить файл inbox (ID, формат),
>    повторить.
> 2. Просмотреть `dict/*.yaml`: у каждой записи нейтральный `title` без значения; `encoding: base64` — где значение
>    с управляющими символами, пробелами по краям или двоичное; наборы `set` — значения одной цели вместе; дубли по
>    смыслу (разница только в регистре или пробелах) — `python ../tools/test_data.py merge <лишний> <оставить>`.
> 3. `python ../tools/test_data.py index`, `env`, `html`.
> 4. Коммит: `dict/`, `../taxonomy/test-data-index.yaml`, записи, изменённые скриптом; сообщение
>    «Словарь тестовых значений: <что сделано>». В ответе — только ID и счётчики.

## 3. Без доступа к репозиторию (web-интерфейс модели)

Если сессия Claude Code остановилась или работу ведёт другая модель в web-интерфейсе:
- **сбор** — `python Api/tools/export_for_llm.py --records ID,ID` даёт архив с этими записями и этим файлом;
  модель возвращает YAML для inbox и исправленные записи; человек кладёт их по местам и делает шаги 4–5;
- **словарь** — человек передаёт модели файлы `dict/` и `inbox/` и раздел 2 этого файла; результат — исправленные
  файлы `dict/`; `merge`, `index`, `env`, `html`, коммит — человек.

## Использование в тестах и разборе

- Генератор коллекции подставляет в запрос `{{TD-…}}` / `{{TDS-…}}` по полю `test_data` записи; значений не видит.
- Вердикт по ответу на такое значение («отражено без экранирования», «текст ошибки СУБД в ответе», «задержка больше
  порога») считает скрипт теста — разбору не нужно тело ответа.
- В отчётах, багах, поиске дублей — `[TD-…]`. Значение для разработчика — по ID: `test-data/build/index.html`
  (позже — pages, KB или сервис), в трекер — ссылкой, не текстом.
