# 0013. Репозитории проекта: документация + тесты (ветки по версиям) и результаты (без веток)

- **Статус:** принято (дополняет [0007](0007-autotest-workspace.md): п. 3 — результаты отдельно — остаётся в силе)
- **Дата:** 2026-10-26
- **Участники:** bj, Claude

## Контекст

Хранение BFF выглядело рассогласованным: тесты, исходная документация (`docs/sources`) и ревью ПМИ (`docs/reviews`)
лежат в репозитории с именем `test/postman` (имя - наследие пилотной генерации), результаты - в `test/autotest/bff`,
рядом пустой `test/autotest/testrun`, устаревший `test/test-runs` и локальные остатки пилота (`C:\Git\postman`,
`C:\Git\postman_`). Нужно: место для исходной документации и её ревью (в т.ч. от заказчика), версии коллекций по мажорным
версиям продукта (финальная коллекция 1.0 остаётся как была), исторические прогоны и отчёты, баги со ссылками на трекер.

## Решение

1. **Два репозитория на проект** в группе `test/autotest`:
   - `<проект>-tests` (BFF - `bff-tests`, бывш. `test/postman`): **документация + тесты**. `docs/sources/` - исходная
     документация (md-копии, контракты, манифест `sources.yaml` со ссылками на оригиналы и sha256, снимок Drive),
     `docs/reviews/` - ревью и анализ документации (наш, заказчика, встречи), `docs/modules/`, `docs/project/`,
     `postman/`, `suites/`, `tools/`. Документация и тесты привязаны к версии продукта - ветка даёт единый срез.
   - `<проект>-results` (BFF - `bff-results`, бывш. `test/autotest/bff`): **результаты** - прогоны, отчёты, баги, история
     Allure, сводки. **Без веток**: прогоны - неизменяемая история, реестр багов и нумерация `BUG-<КОД>-NNNN` - одни на
     все версии (баг, живой в 1.0 и 2.0, - одна запись со статусом и ссылкой на трекер).
2. **Версии в tests**: `main` - текущая работа; приняли версию - тег `<проект>-<версия>` (`bff-1.0`) и ветка
   `release/<версия>` только для исправлений. Новая мажорная версия API - ветка, не параллельные папки; исключение - обе
   версии одновременно живут на стендах: это два контракта - две коллекции ([0010](0010-collection-per-contract.md)).
3. **Связь прогона с версией** - `run.yaml`: репозиторий, коммит, ветка и ближайший тег тестов (движок 0.9.1).
   Прогоны с любой ветки пишутся в `main` репозитория результатов.
4. **Локально** - как в [0007](0007-autotest-workspace.md): `C:\Git\Autotest\projects\<КОД>\tests` (клон
   `<проект>-tests`, ветка переключается) и `...\results` (клон `<проект>-results`). Нет `results` - движок клонирует его
   по `results.url` из `autotest.yaml`, чтобы не забыть второй репозиторий.
5. **Баги** - как прежде ([0003](0003-test-runs-and-bugs.md), `Process/bugs.md`): исправленный и невоспроизводимый
   баг не удаляется, меняется статус.

## Альтернативы

- **Три репозитория** (`docs`, `tests`, `results`) - документация нужна тест-плану и анализу ПМИ, но ветки docs и tests
  пришлось бы держать согласованными вручную.
- **Один репозиторий на всё** (документация, тесты, результаты) - единый срез и один клон, но в release-ветках
  совпадут номера багов, баг на несколько версий раздвоится, история прогонов и тренды Allure разойдутся по веткам,
  коммиты прогонов зашумят историю тестов.
- **Переименовать `testrun` под документацию** - отказ: документация остаётся в tests; `testrun` удаляется, если не
  нужен создавшему.
