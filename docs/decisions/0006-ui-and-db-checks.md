# 0006. Проверки UI и БД в библиотеке

- **Статус:** принято
- **Дата:** 2026-10-16
- **Участники:** bj, Claude

## Контекст

Библиотека создавалась для API-тестов (REST, gRPC, GraphQL, WebSocket). В `Api/ideas/inbox.md` по договорённости
пишутся и идеи UI-тестов (web, desktop, mobile; пометка `UI`) и тестов БД и SQL (пометка `DB`): к разбору inbox
2026-10-16 из 317 идей около 110 — UI и 99 — DB. Решение bj: разбирать inbox целиком, а не только API-идеи; для этого
UI и DB нужно место в библиотеке.

## Решение

1. Библиотека покрывает три слоя: API, UI (web, desktop, mobile) и БД. Формат записи общий (`schema/check.schema.json`),
   принципы те же (ADR 0002: ожидание из всех источников, контракт — лишь часть).
2. Каталоги: `checks/ui/` — проверки интерфейса, `checks/db/` — проверки схемы, ограничений, миграций, запросов и данных.
3. Протоколы (`protocols`) дополнены значениями `ui-web`, `ui-desktop`, `ui-mobile` и `db`. UI-запись для всех платформ
   перечисляет все три; правило APPLICABILITY-04 (протокол проекта совпадает с протоколом записи) не меняется — UI- и
   DB-записи не попадают в API-проект, пока он не заявит эти протоколы.
4. Категории: `ui` (формы, навигация, состояние, отображение данных и ошибок, клиентские настройки, локализация и RTL)
   и `db` (схема и ограничения, миграции, индексы и планы запросов, хранимая логика, целостность данных, служебные запросы
   приложения). Префиксы ID — `UI-` и `DB-`.
5. Метки: `ui` и `db` в группе domain; поведенческие и run-метки — общие.
6. Записи из inbox заводятся со статусом `draft`; `approved` ставит человек (как для выгрузки багов).
7. Генерация UI- и DB-тестов (инструменты, профили запуска) — отдельной задачей; до неё записи используются как чек-листы
   и для ручного или полуавтоматического тестирования.

## Альтернативы

- **Только API-идеи, UI и DB оставить в inbox** — inbox продолжит расти, идеи теряются; отклонено решением bj.
- **Отдельные библиотеки для UI и БД** — дублирование схемы, инструментов и правил отбора; общий формат проще, протоколы
  уже разделяют слои при отборе.

## Последствия

- `schema/check.schema.json` — новые значения `protocols`; `taxonomy/categories.yaml` и `taxonomy/tags.yaml` — `ui`, `db`.
- `Api/README.md` — структура каталогов; корневой `CLAUDE.md` — назначение библиотеки шире API.
- Инструменты отбора (`select_checks.py`) и каталог работают без изменений; генераторы тестов UI и БД пока нет.
- Название каталога `Api/` историческое — переименование не делается (ссылки во многих репозиториях).
