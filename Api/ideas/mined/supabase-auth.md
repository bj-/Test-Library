## Новые идеи

Принятые становятся записями `status: draft` с меткой `real-world-bug` и ссылкой на RWB.

| # | Решение | Запись / файл | Идея | Подтверждающие баги |
|---|---|---|---|---|
| 1 | accept | `AUTH-OAUTH-OUTBOUND-SCOPE` (RWB-0311)<br>`checks/security/authentication-session.yaml` | Запрос авторизации, который сервис отправляет внешнему OAuth/OIDC-провайдеру, содержит в scope запрошенные клиентом значения и не добавляет устаревших или конфликтующих scope по умолчанию | [supabase/auth#1827](https://github.com/supabase/auth/issues/1827) |
| 2 | accept | `AUTH-IMPORTED-PASSWORD-HASH` (RWB-0312)<br>`checks/security/authentication-session.yaml` | Пользователь, импортированный с готовым хешем пароля поддерживаемого алгоритма (bcrypt, scrypt, argon2, PBKDF2 из другой системы), входит по исходному паролю; неверный пароль отклоняется; формат хеша определяется по префиксу или параметрам | [supabase/auth#1750](https://github.com/supabase/auth/issues/1750) |
| 3 | accept | `AUTH-CONTACT-CHANGE-PREVIOUS-VALUE` (RWB-0313)<br>`checks/security/authentication-session.yaml` | Смена телефона или email на ранее использованный этим же пользователем (A → B → A) проходит обычным подтверждением кодом — код отправляется, принимается, значение обновляется | [supabase/auth#1629](https://github.com/supabase/auth/issues/1629) |

текст варианта добавляется шагом (`steps[].action`, в `notes` — RWB). Неверное совпадение — ID бага в
`proofs.exclude`, вариант без нового шага — в `proofs.no_variant`.
