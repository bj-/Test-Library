# 0015. Раздельные прогоны (обычные, безопасность, sg-restricted, разрушающие) и выбор модели для разбора

- **Статус:** принято (дополняет [0011](0011-security-groups.md) и [0014](0014-restricted-records-in-child-sessions.md))
- **Дата:** 2026-10-29
- **Участники:** bj, Claude

## Контекст

Прогон модуля шёл одним набором (`full.yaml`). Из него отдельно выделялись только разрушающие тесты (`only: destructive`)
и группы безопасности после прогона (`autotest.py split`). Разбирают результаты разные исполнители: обычные тесты -
основная сессия, группы `child` - дочерняя сессия на модели с низким фильтром (сегодня `claude-opus-4-8`), `sg-restricted`
- человек (ADR 0014). Общий прогон всё равно приходилось делить, а основная сессия видела состав рискованных групп.

Разбор дорогой: его ведёт старшая модель. Какая модель минимально достаточна, не проверялось - решение bj 2026-10-29:
сравнить на одном прогоне разборы моделей разных семейств последних версий и выбрать самую дешёвую, чей разбор совпадает
с образцом.

## Решение

1. **Четыре прогона модуля** (движок 0.11.0, поле набора `only`) - части делят коллекцию без пересечений:

   | Набор | Отбор | Разбирает |
   |---|---|---|
   | `functional.yaml` | `only: functional` - тесты без групп `sg-...`, без разрушающих | основная сессия |
   | `security.yaml` | `only: security`, `exclude_groups: [sg-restricted]` - группы безопасности, без разрушающих | по группам (`split`), исполнитель группы |
   | `security-restricted.yaml` | `only: security`, `tags: [sg-restricted]` | человек (ADR 0014); запуск - дочерняя сессия |
   | `destructive.yaml` | `only: destructive` - только по явному решению (`--destructive yes`) | по группе теста (у BFF-Mobile все - `sg-restricted`) |

   `full.yaml` остаётся для полного прогона одним запуском; разбирать его - через `split`.
2. **Выбор модели для разбора** - по каждой части, на одном и том же прогоне:
   - **образец** - разбор исполнителя части: обычные и группы `self` - основная сессия (сегодня Opus 5.5), группы `child`
     - `executors.child.model` (сегодня `claude-opus-4-8`);
   - **кандидаты** - по одной дочерней сессии `claude -p --model <модель>` с тем же заданием, от дорогой к дешёвой:
     `claude-sonnet-5-5`, затем `claude-haiku-5-5`; для групп `child` после `claude-sonnet-5-5` -
     `claude-sonnet-4-6`, `claude-haiku-4-5` (у моделей 5.5 фильтр может остановить разбор - это и проверяется).
     Haiku - только если Sonnet совпал. Модель сверять по `modelUsage`, не по ключу `--model`;
   - кандидат пишет только таблицу «Разбор и баги» в копию отчёта части `report.<модель>.md` рядом с `report.md`;
     багов не заводит, `bugs/` и трекер не трогает;
   - сравнение - `autotest.py compare-triage <report.md образца> <report.<модель>.md>`: ключ - тест и утверждение,
     сравниваются категория причины (таблица «Разбор» `Process/running-tests.md`) и баг (нужен / номер существующего).
     Для частей, содержимое которых основной сессии не видно, - `--counts` (только числа);
   - **достаточна** - модель, чей разбор совпал с образцом, или расхождения человек признал ошибками образца. Итог -
     в STATUS проекта (часть, модель, совпало N из M, стоимость); смена исполнителя разбора - решение bj по итогу.
3. Пока выбор не сделан, разбор ведёт образец (как сейчас). Справятся Sonnet или Haiku - решение пересматривается
   (bj 2026-10-29), исполнитель разбора записывается отдельно от исполнителя генерации.

## Альтернативы

- Один прогон и `split` после него - так и было; основная сессия видит общий отчёт с составом всех групп, разрушающие
  тесты смешаны с остальными.
- Сравнивать разборы на глаз - нет числа «совпало N из M», при смене модели не повторить.
- Сразу перевести разбор на дешёвую модель - без образца не узнать, что она пропускает.

## Последствия

- Движок 0.11.0: `only: security | functional`, `exclude_groups`, `run --exclude-group`, команда `compare-triage`.
- Проекты заводят четыре набора модуля (образец - `bff-tests`, `suites/BFF-Mobile/`).
- Сравнение стоит лишних дочерних сессий на одном прогоне; дальше разбор дешевле, если кандидат совпал.
- Связано с идеей bj 2026-10-29 (STATUS `bff-tests`): цикл безопасности целиком - отдельным раном на старой модели, без
  участия основной сессии; раздельные прогоны - первый шаг к ней.
