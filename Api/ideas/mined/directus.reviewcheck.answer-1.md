## Что объединить или разделить

1. Идея 1 — один паттерн из двух багов. Оставить единую запись о согласованности фильтров между операциями, но перечислить операции и глубину вложенности как независимые измерения тестового набора. Не ограничиваться только GraphQL, если аналогичный риск воспроизводим через другие интерфейсы API.
2. Идея 2 — не превращать в одну огромную матрицу. Проверка динамических переменных в авторизации и проверка переменных в валидации связаны, но отличаются по ожидаемому результату. Для первой важны разрешение/запрет доступа, для второй — принятие/отклонение данных. Общий принцип эквивалентности можно переиспользовать, а наборы проверок оставить отдельными или связанными через `extends`.
3. Идея 9 — обязательно сузить. Сейчас она объединяет загрузку, скачивание, трансформации, Range и удаление. Это разные инварианты. Исходный баг обосновывает только доступность изображения с preset/key при конкретном хранилище. Общую матрицу совместимости хранилищ можно сделать профилем запуска для нескольких записей, а не одной записью на все файловые операции.
4. Идея 6 — не смешивать два разных дефекта. Создание пустого пользователя при отправке пустых данных — отдельное поведение записи. Потеря существующей записи связующей таблицы при чтении — отдельный дефект чтения. Представленная идея покрывает второй, а первый стоит отдельно рассмотреть, если это допустимый для библиотеки самостоятельный риск.

## Что здесь не про API

Полностью не-API паттернов среди десяти идей нет: все можно проверять через публичный интерфейс сервиса, включая WebSocket и операции с файлами.

Однако для идеи 3 есть оговорка: длительная работа планировщика — это интеграционная проверка API и фонового процесса, а не обычный тест одного HTTP-запроса. Ей нужен специальный профиль запуска. Сдвиг системного времени допустим лишь при наличии надёжного механизма управления временем; иначе он может не воспроизвести реальный дефект таймера.

Для идеи 9 тесты на нескольких драйверах также требуют соответствующей инфраструктуры. Отсутствие конкретного драйвера в окружении — это неприменимость теста в данном профиле, а не доказательство отсутствия дефекта.
