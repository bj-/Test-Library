1. выложить библиотеку в общий доступ, но сохранить возможность монетизации генератора.
Как показал первый опыт использования - генератор тестов с библиотекой дает гораздо более высокое качество тестов и покрытие чем без и даже чем попытки сгенерировать похожий прогон имея уже сгенерированный набор тестов (прогон).

Варианты:
Web + API - что бы генератор прогонов мог опирасться на библиоттеку и накопленные в ней знания

Пожелания:
* невозможность стянуть библиотеку локально и игнорировать желание разработчика монетизации генератора

Открытые вопросы:
* может ли такая библиотека генерировать тесты используя только скрипты?
В каком месте необходим LLM для создания прогонов?

2. LLM при генерации тестов подгружает файлы библиотеки, что дает очень большой контекст и большое потребление токенов. Как лучше уменьшить размер контекста? хранть в БД и отдавать через API только нужное для генарции тестов по конкретным ручкам? Предложи идеи
Экономия токенов - относится к тому что в тех местах где требуется привлечение LLM для генерации (учет требований, фактического исходного кода, документации) и полученная информация влияет на решение о дополнительных тестов и/или тестов ловящие уже существующие в коде проблемы для их подсветки.
