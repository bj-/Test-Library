# 0019. Проба: sg-restricted целиком на Sonnet 5.5 - генерация, прогон, разбор и работа человека

- **Статус:** принято, временное исключение из [0014](0014-restricted-records-in-child-sessions.md) на время пробы
- **Дата:** 2026-11-05
- **Участники:** bj, Claude

## Контекст

ADR 0014: записи стоп-тем (`sg-restricted`) генерирует `executors.child.model` (`claude-opus-4-8`) по одной записи на
дочернюю сессию, оркестратор «вслепую»; разбор прогона `groups/sg-restricted/`, тело багов `AI-доступ: restricted`,
решение о неприменимости и снятие `[DRAFT]` - человек. ADR 0018 (проба Sonnet на генерации) `sg-restricted` не затрагивал.

На BFF-Mobile `claude-sonnet-5-5` без единой остановки фильтра собрал тесты всех остальных групп безопасности (партии
s1-s8, 2026-11-02/03) и разобрал их прогоны (ADR 0015: 94/97 строк с образцом, 2026-10-30; полный прогон
BFF-20261103-161151-full - 2026-11-05). Работа человека по `sg-restricted` - узкое место: 17 падений прогона 2026-11-03
и 10 записей `human` в базе модуля ждут его.

## Решение

Решение bj 2026-11-05: на время пробы `sg-restricted` ведёт `claude-sonnet-5-5` в дочерних сессиях - **включая то, что
по ADR 0008/0014 делает человек**:

1. **Генерация** - записи `decision: human` базы модуля: одна запись - одна дочерняя сессия Sonnet 5.5; неприменимость
   решает она же (обоснование в docstring спецификации).
2. **Прогон** - набор `security-restricted` модуля (как в ADR 0015); запускает дочерняя сессия или основная - движок
   показывает в выводе только счётчики; отчёт части основная не читает.
3. **Разбор** - `groups/sg-restricted/report.md`: таблица «Разбор и баги», баги `AI-доступ: restricted` **с телом**
   (в `restricted/` репозитория результатов), снятие `[DRAFT]` по итогам.
4. **Доступ дочерней сессии** к закрытому: запуск из каталога проекта с `--setting-sources user` - проектные запреты
   `.claude/settings.json` не загружаются, хук `project-deny-guard.js` в сессию внутри проекта не вмешивается. Других
   послаблений нет: `--allowedTools` минимальный, `--max-budget-usd` на сессию.
5. **Основная сессия - оркестратор «вслепую»**, как в ADR 0014 п. 2: закрытое не читает; итог дочерней - нейтральный JSON
   (ID, счётчики, вердикт); проверка - скриптами без содержимого (lint, `meta`, `security_groups.py check`, счётчики
   строк разбора против числа упавших утверждений, `git diff --numstat`).
6. **Остановка фильтра** у Sonnet 5.5 - фрагмент не повторять; та же единица работы идёт по лестнице ADR 0014
   (`claude-opus-4-8` -> `claude-sonnet-4-6` -> `claude-haiku-4-5`), о переходе - bj; проба считается «с остановкой».

restricted` не заведено: все падения отнесены к известным багам формы ошибки - это bj стоит проверить выборочно.

**Второе мнение (2026-11-05):** Codex (GPT-6 Codex, простая модель Luna, с доступом к коду) и ChatGPT (GPT-6, только
набор данных) - задание и набор: bff-tests `docs/prompts/second-opinion/`, `tools/second_opinion_pack.py`. Разбор -

Вердикт обоих - «нет»; сводка дочерней сессией Sonnet (нейтральная выжимка для оркестратора, полный текст - у bj в
`.local/second-opinion-restricted/digest.md`): ошибки Sonnet - 3 (ожидания S196, S211, S212 его новых тестов),
ограничения среды - 5 (заглушка core, проверка через почту, внешний файловый хост, нет наборов TD), ошибки рецензентов -
2, спорных - 7; предусловие S177-S181 - тесты opus-4-8 (эксперимент 2026-10-28), Sonnet верно разобрал как «дефект
теста», исправление в задание не входило. Рекомендация сводки - accept_with_fixes.

**Исправления (Sonnet 5.5, 1,71 $, отказов 0):** S177-S181, S196, S211, S212 исправлены; INJ-OS-COMMAND и INJ-NOSQL
перепроверены по коду `bff-mob` (срез `origin/dev`, развёрнут на стенде) - «не применимо» подтверждено с обоснованием по
коду. Перепрогон BFF-20261105-124909-security-restricted: 41 тест, ✅29 ❌12 (было 27/14), разбор 12/12 - все падения -
дефекты продукта (BUG-BFF-0028, 0051), дефектов теста 0. Итого проба - 9,92 $.

**Вывод для решения:** в своей части Sonnet 5.5 справляется (остановок 0, разбор подтверждён, ошибки - в ожиданиях
новых тестов, исправлены по замечаниям). Условие, которое выявила проба: решение «не применимо» принимается только с
проверкой по коду продукта (срез развёрнутой ветки), а не по контракту; новые тесты рискованных тем - со вторым мнением,
пока не накопится статистика.

**Решение по итогу - bj** (после выборочной проверки разборов и решений о неприменимости):

- Без остановок и с разбором, который bj признал годным -> Sonnet 5.5 ведёт `sg-restricted` и дальше, человек из
  обязательных шагов исключается (новый ADR, заменяющий п. 1 и 4 ADR 0014; правки `security-groups.yaml`,
  `Process/security-groups.md`, `Process/bugs.md`, память `ai-generation-restrictions`, `security-group-sessions`).
- Остановки или брак -> исключение снимается, действует ADR 0014.

## Альтернативы

- Оставить разбор человеку (ADR 0014 как есть) - узкое место остаётся.
- Проба только на разборе, без генерации - не проверяет основную цель (исключить человека из всей цепочки).

## Последствия

- Закрытые материалы видит дочерняя модель с фильтром новее 4.8: риск остановки - он и проверяется.
- Качество тел багов и решений о неприменимости без человека - проверяет bj выборочно по итогам пробы.
