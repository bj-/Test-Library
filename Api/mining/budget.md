# Журнал расхода лимита Claude на выгрузку багов

Норма — не больше **5 % недельного лимита в день** на все машины вместе (ADR 0004). Перед партией проверить сумму
за сегодня; партия, которая не уложится в норму, не начинается. Значения — по `/usage` («Current week»).

| Дата | Машина | Шаг / партия | Багов | Неделя до, % | Неделя после, % | Расход, % | Заметки |
|---|---|---|---|---|---|---|---|
| 2026-10-13 | bj (Windows) | калибровка: триаж + абстракция + сопоставление, `cal-01` | 20 | 41 | 41 | < 1 | Шкала недели целочисленная, изменение не видно; сессия 30 → 36 % (вместе с написанием `batch.py`). Оценка сверху: ≤ 1 % на 20 багов → норма ≤ 100 багов в день |
| 2026-10-13 | bj (Windows) | триаж + абстракция + сопоставление, `p-01` | 50 | 41 | | | |

## Текущая норма

По двум замерам (`cal-01` + `p-01`): 70 багов вместе с написанием скриптов — неделя 41 → 42 %, то есть от 0,01 до 2 %
(шкала целочисленная). Оценка сверху — 2 % на 70 багов, около 0,03 % на баг.

**До 150 багов в день** (≈ 4,3 % недели, запас до 5 %). Пересчитать после следующих партий.

Шкала сессии точнее недельной: за эти партии сессия выросла на 10 %, а неделя — примерно на 1 %. Для оперативного
контроля: **5 % недели ≈ 50 % сессии**. Перед партией сверять расход за день по этому журналу.

Расход растёт с длиной разговора: каждый ход отправляет весь контекст заново. Партии лучше обрабатывать в свежей
сессии (состояние — в `docs/STATUS.md`, `build/mining/<batch>/batches/`).
