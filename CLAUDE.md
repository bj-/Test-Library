# Test-Library — API Test Library

Версионируемая библиотека шаблонов проверок для генерации API-тестов REST и gRPC (код и данные — в `Api/`).
Принципы, структура и формат записей — в `Api/README.md`.

## Где что лежит

- `Api/docs/` — документация самой библиотеки (обзор, план реализации, отчёты по этапам, каталог).
  Не путать с корневым `docs/` — там состояние работы и решения.
- `Api/build/` — сгенерированные отчёты покрытия.
- План реализации — `Api/docs/IMPLEMENTATION_PLAN.md`, отчёты по этапам — `Api/docs/STAGE_REPORTS.md`.

## Связанные репозитории

- `postman` — коллекции, построенные по библиотеке; реальные контракты — `Api/examples/real-contracts/`.

## Общий контекст проекта

Над проектом работают несколько человек с разных машин. Локальная история и память
Claude Code между машинами **не переносятся**, поэтому всё состояние работы хранится в репозитории:

| Файл | Назначение |
|---|---|
| `docs/STATUS.md` | Текущее состояние: в работе, следующие шаги, блокеры, журнал |
| `docs/ideas.md` | Бэклог идей, ещё не взятых в работу |
| `docs/decisions/` | Принятые решения (ADR), по одному файлу на решение |

## Правила работы для Claude

- **В начале сессии** прочитать `docs/STATUS.md` (и при необходимости `docs/ideas.md`).
- **В конце значимого шага** обновить `docs/STATUS.md`: что сделано, что дальше, добавить строку в журнал
  (дата, кто/машина, кратко).
- **Принято архитектурное или процессное решение** → новый файл `docs/decisions/NNNN-краткое-название.md`
  по шаблону `docs/decisions/0000-template.md`, ссылка на него в `STATUS.md`.
- **Появилась идея, не относящаяся к текущей задаче** → добавить в `docs/ideas.md`, а не реализовывать сразу.
- Состояние проекта не сохранять в локальную память Claude — только в эти файлы.
- Изменения в `docs/` коммитить вместе с кодом, к которому они относятся.
