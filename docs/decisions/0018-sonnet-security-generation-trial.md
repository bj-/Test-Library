# 0018. Проба: генерация тестов безопасности на Sonnet 5.5 без деления сессий по группам

- **Статус:** принято, проба (дополняет [0011](0011-security-groups.md), итог - раздел «Итог пробы»)
- **Дата:** 2026-11-02
- **Участники:** bj, Claude

## Контекст

Генерация безопасности шла дочерними сессиями `claude-opus-4-8` по группам. Сборка BFF-Mobile по новой библиотеке - 66
записей безопасности. Расчёт по журналам сессий 2026-10-23..30 (запись кэша 1 час, x2; формула совпала с замером разбора
8,29 $): 7 сессий на 4.8 - 62-68 $, на `claude-sonnet-5-5` - около 25 $ при том же числе ходов. Sonnet 5.5 проверен на разборе (все 70 строк
безопасности совпали с образцом, остановок нет, ADR 0015) и на подборе записей (ADR 0016), на генерации - нет: остановки
фильтра и качество тестов неизвестны.

Деление сессий по группам введено ради остановок фильтра: сессия не держит все темы сразу, остановка теряет одну группу.
Если Sonnet не останавливается, деление только добавляет запуски: размер партии выгоднее выбирать по числу ходов (30-60).

## Решение

Решение bj 2026-11-02.

1. **Генерация безопасности - на `claude-sonnet-5-5`:** `executors.child.generation_model` в `security-groups.yaml`.
   Разбор тоже Sonnet 5.5 (рекомендация `Process/running-tests.md`), `executors.child.model` для остального не меняется.
2. **На время пробы п. 4 ADR 0011 («одна группа - одна сессия») на генерации на Sonnet не действует:** партии по 6-12
   записей могут смешивать группы. Порядок - от низкого риска к высокому (`sg-token`, `sg-session`, `sg-login`,
   `sg-injection` - после остальных), чтобы ранняя остановка не задела остальное.
3. **Не меняются:** `sg-restricted` - по ADR [0014](0014-restricted-records-in-child-sessions.md), закрытые материалы -
   ADR [0008](0008-ai-restricted-isolation.md), значения по ссылке `TD-…` - ADR
   [0009](0009-test-data-by-reference.md), проверка работы дочерней сессии скриптами. Метки групп на тестах и отчёты по
   группам остаются: делить прогон и разбор они не мешают.
4. **Итог пробы:**
   - ни одной остановки на всех партиях - ограничение снимается совсем с пометкой «только на Sonnet»;
   - остановка - разделение по группам остаётся: остановленную партию делить по ADR 0011, исполнитель -
     `executors.child.model`, фрагмент не повторять, тему - в стоп-темы (раздел «Остановка фильтра» `Process/security-groups.md`).

## Альтернативы

- Группы по отдельности на Sonnet - надёжнее при остановке, но проба не покажет, можно ли обойтись без деления.
- Оставить `claude-opus-4-8` - дороже в 2,5 раза, цена проверена, но экономии нет.
- Сразу снять ограничение - без пробы неизвестно, остановит ли фильтр Sonnet.

## Последствия

- Остановка в смешанной партии теряет её целиком, а не одну группу; партия мала, потеря ограничена.
- Остановка показывает одну тему на партию: группу определять по записям партии.
- `executors.child.generation_model` действует только на генерацию; `security_groups.py stats` по-прежнему показывает
  `model`.
