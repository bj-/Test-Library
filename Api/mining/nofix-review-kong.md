## Как использовать (для внутренней сессии)

- Это **не** результат триажа по `prompts/triage_abstract.md`: `batch.py check`, `cluster.py` и `apply_proofs.py` этот
  файл не читают. Это ручная оценка «хорошая ли идея теста» по багам, которые `filter.py` отбросил (нет PR/коммита).
- Идеи отсюда уже перенесены в `ideas/inbox.md` (строки с пометкой «kong, баг без фикса», см. «Перенос в inbox»
  ниже) и разбираются как обычный inbox: семейство F* → запись(и) в `checks/` или шаги существующих; **П** → шаг
  или пруф к записи из колонки «Куда»; **Д** — уже учтены через исправленный баг-дубль.
- Ожидание в таких идеях взято из стандартов и здравого смысла, а не из тестов фикса: исправления нет, поведение
  разработчиком не подтверждено. Это допустимо по ADR 0002, но в записи `expected_source` — стандарт или «практика».
- Дальше такие баги идут через существующий механизм: `allow_no_fix` в `sources.yaml` → `filter.py` оставляет их с
  `fix_evidence: closed-completed`. Как их триажить — решение внутренней сессии (промпт триажа, ADR).

Обозначения: **С** — основа семейства проверок; **С+** — член семейства; **П** — пруф или вариант к существующей
записи; **Т** — отдельная новая проверка; **Д** — повтор бага, уже разобранного с исправлением; **Н** — не тест
(сборка, документация, вопрос, CLI и миграции, внутренности, мало данных). UI/DB — идея для этих направлений.
