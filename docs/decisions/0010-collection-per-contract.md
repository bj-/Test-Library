# 0010. Коллекция = контракт: каркас коллекции - дерево контракта со всеми ручками

- **Статус:** принято
- **Дата:** 2026-10-22
- **Участники:** bj, Claude

## Контекст

Коллекции собирались только из ручек, по которым сгенерированы тесты (BFF: модули BFF-Mobile-OnStart, -Documents,
-Stories по одному мобильному контракту). В коллекции не видно, какие ручки вообще есть и какие не покрыты: 4 ручки
`auth` мобильного контракта без тестов были видны только в STATUS. Описания, параметры и варианты ответов контракта
приходилось искать в самом контракте.

## Решение

1. **Одна коллекция = один контракт** (тестируемый сервис). Прежние модули по одному контракту - папки его путей.
2. **Каркас - дерево путей контракта**, как при импорте OpenAPI в Postman: `/api/auth/send-code` -> `api/auth/send-code/`
   (у пути несколько методов - подпапка на метод); строит генератор целиком, включая ручки без тестов. В папке
   операции - заготовка `[Контракт] <METHOD> <operationId>`: описание, параметры, пример тела, примеры ответов на каждый
   код (`.example.yaml`); не отправляется (движок - вид `example`, Postman - только с переменной `sendContract`).
3. **Где лежит тест - по его цели.** Цель - конкретная ручка: в её папке; папку определяет путь запроса теста, исключение
   (тест через несколько ручек, запрос не на проверяемую) - явно (`target`). Цель - много ручек с одной проверкой (матрица AuthN, заголовки, перебор): вне дерева, в папке по группе
   проверок (`SECURITY`, ...).
4. **Покрытие** считает генератор: по операции - тесты и проверенные коды ответа контракта (по методу и пути запроса);
   сводка - в описании коллекции и папки операции, `coverage.md` модуля. Ручка без тестов - «❗ не покрыта».
5. Ручка вне контракта (стенд, код) и ручка, пропавшая из контракта при наличии тестов, - `Вне контракта/<операция>`:
   находка; тесты не удаляются до разбора.
6. Заготовка - справка, не ожидание (ADR 0002).

Правила - `Process/collections.md`, п. 3; навык `create-tests-api`, шаг 5. Реализация - общий модуль движка
`test-engine` `engine/contract_tree.py` (0.8.0): генераторы проектов передают ему тесты и получают дерево.

## Альтернативы

- Отдельная справочная коллекция контракта рядом с тестовыми - две коллекции на сервис, покрытие не видно на месте.
- Только таблица покрытия в README и отчёте - список ручек есть, но в Postman по-прежнему не видно контракта.
- Коллекция по модулю (как было) - ручки контракта без модуля нигде не видны, один контракт - несколько коллекций.

## Последствия

- Пути тестов меняются (`api/<путь>/...`), имена тестов - нет: баги, ссылающиеся по имени, не ломаются;
  наборы `suites/` и правила `test_meta.yaml` - переписываются под новые пути.
- Запуск части сервиса - набор с папкой пути в `items` (`api/documents/`, движок `test-engine` 0.7.0).
- Дерево - по путям, а не по тегам (уточнение bj 2026-10-22): человеку привычнее дерево, как Postman строит из
  контракта; тег операции - в описании заготовки и в таблице покрытия.
- Пример - проект BFF, коллекция `BFF-Mobile` (ADR BFF 0006).
