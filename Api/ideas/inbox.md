# Входящие идеи тестов

Сюда записываются **все** идеи проверок, возникшие по ходу работы (прогоны, разбор багов, чтение контрактов и ТЗ),
сразу, без проверки на дубли и актуальность. Разбор - отдельной задачей: идея либо становится записью в
`checks/` (в «Статус» - её `check.id`), либо дополняет существующую, либо отклоняется с причиной.

Цель - библиотека с большим количеством качественных идей тестов: лучше записать лишнее, чем потерять.

UI-идеи (web, desktop, mobile) тоже записываются: библиотека будет расширяться на генерацию UI-тестов.
Такие идеи начинаются с пометки `UI` и платформ, если идея не для всех (`UI web`, `UI mobile`).
Так же записываются идеи тестирования БД и SQL (схема, процедуры, триггеры, данные) — с пометкой `DB`.

Формат: одна строка - одна идея. «Откуда» - проект/прогон/баг, где идея возникла; «Пример» - наблюдение,
на котором она основана (если есть). Статус: `new` | `→ <check.id>` | `отклонено: <причина>`; `→ <check.id> (шаг)` — идея стала шагом существующей
записи, `→ <check.id> (покрыто)` — уже покрыта ею.
