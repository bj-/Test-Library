### Идеи для разбиения/склеивания и паттерны не про API

- **Идея 5** содержит два разных бага: (а) изменение сериализации пустых полей вызывает побочные раскатки, (б) разные версии при rolling update пишут в один ConfigMap по кругу. Оба паттерна относятся к **стабильности состояния при обновлении**, поэтому склеены в одну запись `COMPAT-STATE-STABILITY-ON-UPGRADE`.
- **Идея 4** (перечитывание сертификатов с диска) и **Идея 7** (корректность эндпоинта flagz) требуют доступа к файловой системе узла или процессу запуска сервиса. Это граничные случаи: они проверяются через API (подключением или чтением эндпоинта), но подготовка тестовых данных (замена файла, запуск с флагами) требует инфраструктурного доступа.
- **Идея 2** — это паттерн внутренней логики авторизатора (обход графа связанных объектов), а не инвариант API. Внешний API-тест не может надежно воспроизвести состояние «связанный объект не найден, но явное право есть», так как это специфика реализации Kubernetes RBAC/ABAC.

### Общий вывод

Систематическая ошибка кластеризации в этой партии — попытка превратить баги внутренней реализации (обход графа в авторизаторе, специфика CSI-миграции, внутренняя сериализация etcd) в универсальные API-тесты. Успешно обобщены только те идеи, которые затрагивают границы взаимодействия: паритет версий HTTP, восстановление после смены бэкенда, консистентность идентичности при разных схемах входа и стабильность пулов ресурсов при soft-delete.
