# Группы проверок безопасности - работа по группам

Решение - ADR [0011](../docs/decisions/0011-security-groups.md). Каждая группа - отдельная сессия ассистента на каждом
этапе; сессия видит только свою группу. Изоляция ADR 0008 (закрытые подробности) и ADR 0009 (тестовые значения по
ссылке `TD-…`) действует как прежде.

## Группы

Список и правила - `Api/taxonomy/security-groups.yaml`, состав - `python Api/tools/security_groups.py stats`.

| Группа | Что | Риск остановки |
|---|---|---|
| `sg-token` | токены и проверка аутентификации запроса: JWT, подпись, alg, aud/iss, сроки, тип токена | низкий |
| `sg-session` | refresh и его повтор, выход и его область, отзыв, cookie, CSRF | средний |
| `sg-login` | вход: одноразовые коды, пароли, MFA, OAuth/OIDC/SAML, нормализация логина | средний |
| `sg-authz` | роли, владение объектом, тенанты, scope | низкий |
| `sg-injection` | инъекции (значения - только по ссылке TD) | средний |
| `sg-privacy` | персональные данные: маскирование, утечки, удаление | низкий |
| `sg-hardening` | заголовки, CORS, TLS, отладочные ручки, лимиты, прочее | низкий |
| `sg-restricted` | стоп-темы - только заготовки `[DRAFT]` и человек | - |

Порядок групп в модуле - от низкого риска к высокому: так остановка на рискованной группе не мешает остальным.

## Кто ведёт группу (исполнитель)

Поле `executor` у группы в `security-groups.yaml` - **логическое имя** (не конкретная модель) из таблицы `executors`
того же файла (ADR 0011, решение bj 2026-10-23); `python Api/tools/security_groups.py stats` печатает
`[риск/исполнитель (модель)]`:

- `self` - основная сессия ассистента ведёт группу сама (низкий риск остановки: `sg-authz`, `sg-privacy`, `sg-hardening`);
- `child` - рутину (генерация, прогон, разбор, баги) ведёт **дочерняя сессия** `claude -p --model <executors.child.model>`,
  её запускает основная сессия (память `child-sessions-allowed`); группы `sg-token`, `sg-session`, `sg-login`, `sg-injection`,
  где фильтр останавливает основную сессию. Модель с низким фильтром на сегодня - `claude-opus-4-8`;
- `human` - только человек (`sg-restricted`).

**Модель не зашита в группы.** Когда 4.8 выведут, правится только `executors.child.model` в `security-groups.yaml` -
группы не трогаются. «Более старой» с низким фильтром может оказаться и модель другого семейства Claude - Sonnet или
Haiku, в том числе старой версии (`claude-sonnet-*`, `claude-haiku-*`): сначала перебрать их через тот же
`claude -p --model`. На `external` (внешняя/локальная LLM) переходить, только если подходящей модели Claude нет.

**Если дочерняя сессия тоже останавливается** (`executors.child.on_filter_stop: external`) - она не повторяет фрагмент
(память `ai-generation-restrictions`), а основная сессия формирует задание для **внешней/локальной LLM**:
`python Api/tools/export_for_llm.py --group <G>` (без закрытых частей), ответ модели проверяет скрипт и подставляет в
репозиторий дочерняя сессия (как при сборе значений inj-a, `Process/test-data.md`, раздел 3). Кандидаты -
`executors.external.targets` (локальный Qwen для простой рутины, затем ChatGPT и др.). Выбор исполнителя - не обход
ограничения, а его обход в рамках изоляции.

## Этапы

Во всех командах `<G>` - группа сессии.

1. **Генерация тестов.** Записи группы - `python Api/tools/security_groups.py list <G>` (заголовки) - пересечь с
   записями, которые берёт модуль. Сессия читает только эти записи; тестовые значения - `{{TD-…}}` по полю `test_data`.
   После генерации - `python autotest.py meta <коллекция>`: тесты получают метку `<G>`.
2. **Прогон.** `python autotest.py run <набор> --group <G>` - прогон одной группы; или общий прогон и
   `python autotest.py split <каталог прогона>` - `groups/<группа>/report.md` на каждую группу.
3. **Разбор.** Сессия группы читает `python autotest.py view <прогон>/groups/<G>/report.md` (или отчёт прогона
   группы), заполняет «Разбор и баги» в нём; в общий отчёт прогона - строка со ссылкой на отчёт группы.
   `groups/sg-restricted/` ассистенту закрыт - разбирает человек.
4. **Баги.** В шапке - `| Группа | <G> |` (тест нескольких групп - через запятую). Свои баги -
   `python autotest.py view <results>/bugs --group <G>`. В трекер - `file-bugs`, тег группы ставится сам.
5. **Дубли.** `python autotest.py dupes <BUG> --group <G> [--tracker]`; совпадение с багом чужой группы печатается без
   темы - в баг строку «Возможный дубль: <ID>» и попросить человека сравнить. Задачи трекера -
   `yt.py search "<запрос>" --group <G>` (или `--skip-group sg-restricted`), `yt.py show <ID> --group <G>`.

**Проверка после этапа исполнителя `child`** (решение bj 2026-10-23, память `child-sessions-allowed`): в скриптах
старшей или более простой модели ошибки вероятнее, итог её сессии не принимается на веру. Основная сессия проверяет
скриптами, не показывающими содержимое: `git show --stat` (чужие и закрытые файлы не задеты), lint и `meta` коллекции,
`python Api/tools/security_groups.py check <коллекция> --group <G>` (значения вне `{{TD-…}}` - печатает файл, поле и
класс, без значения), сверка заявленных чисел с посчитанными; формулировки итога («остановка фильтра» и т.п.) - с
фактом. Логика тестов рискованных групп проверяется разбором прогона. Нет значения в словаре - тест не писать, а
указать в итоге «нет значения TD: <запись>».

## Промпт сессии группы

```
Работаем только с группой безопасности <G> (Test-Library/Process/security-groups.md, ADR 0011).
Модуль <Модуль>, проект <путь проекта тестов>. Этап: <генерация | разбор прогона <каталог> | баги | дубли>.
Записи, тесты, отчёты и баги других групп не читать; чтение - только командами с --group <G>.
Остановка фильтра - сразу сказать, что сделано и что нет, и спросить, как продолжать.
```

По умолчанию работы по группам идут в дочерних сессиях (решение bj 2026-10-23). Исполнитель `child`: основная сессия
запускает дочернюю этим промптом - `claude -p "<промпт>" --model <executors.child.model>` из каталога проекта тестов
(контекст группы закрыт запретами `.claude/settings.json`). `self` - основная сессия работает по тому же промпту без
дочерней.

## Остановка фильтра

Сказать пользователю, что сделано и что нет; тему - в `ai-stop-topics.yaml`, запись - под флаг
(`restrict_records.py --suggest` -> `--flag`, решение человека), затем `security_groups.py index` - запись уходит в
`sg-restricted`. Повторять остановленный фрагмент нельзя (память `ai-generation-restrictions`).
