## Наблюдения

- **nest и express** закрывают исправленное без привязанного PR («fixed in vX» в комментарии). Для них включён

### Стоимость

- Шаги 3–5 (триаж, абстракция, сопоставление) на 696 багов: ≈ 5,7 % недельного лимита (сумма по `budget.md`;
  `cal-01` + `p-01` оценены по среднему 0,008 % на баг). Это ≈ **0,8 % недели на 100 багов**,
  ≈ **0,11 % на принятую идею**, ≈ 0,02 % на пруф.
- Шаги 6–7 (кластеризация 73 паттернов, 50 записей `draft`, инструменты) — одна сессия; `/usage` не снимался,

  дороже на баг из-за чтения справочников.

### Точность триажа и сопоставления

Разметка — `ideas/mined/pilot.accuracy.xlsx` (50 решений триажа и 30 сопоставлений, цель ≥ 85 %; `tools/mining/accuracy.py`).
Первый проход Claude по первоисточникам (2026-10-15, `pilot.accuracy.claude.yaml`): триаж — 1 расхождение и
4 сомнения из 50 (≈ 98 % без сомнений), сопоставление — 2 расхождения и 5 сомнений из 30 (≈ 92 %). Типичные
ошибки: способ атаки выведен из CWE, а не из текста advisory; парсеры с квадратичной сложностью привязаны к
`INJ-REDOS` (только regex) вместо `HARD-EXPENSIVE-OPERATION-LIMITS`; баг темы входа принят за API.

библиотеку без ревью: пруфы и варианты проходят шаг 7 у человека.

### Выводы

1. **Конвейер окупается.** 1022 собранных бага → 50 новых записей и пруфы у 129 существующих (доля записей
   с пруфами — 47,5 %). Доля принятых на ревью — 94 %, но ревью было целиком по предложению Claude, без
   независимой проверки; реальную точность покажет выборка.
2. **Лучшие источники — продукты-API и advisory.** Keycloak — 8,5 идеи на 100 собранных (авторизация, токены,
   сессии). GHSA — 6,5 идеи и 70 пруфов на 100, доля API 79 %, при этом не нужен фильтр по меткам. Directus —
   5,3 идеи на 100 (фильтры, права, GraphQL).
3. **Фреймворки дают мало.** NestJS и Express — доля API 22–24 %, по 2,5 идеи на 100: почти весь объём —
   внутренности фреймворка (DI, жизненный цикл, логгер), сборка и ошибки использования. Это ≈ 37 % потраченного
   лимита при 14 % идей. body-parser, cookie, express-session исчерпаны (21 баг на троих).
4. **Пробелы библиотеки, которые пилот не закрыл.** Пруфов почти нет у gRPC (1 из 33), GraphQL (1 из 11),
   совместимости и идемпотентности — в источниках пилота таких багов почти не было.

### Рекомендации

- **Масштабировать:** GHSA — на другие экосистемы (PyPI, Maven, Go, RubyGems) с тем же CWE-фильтром; Keycloak —
  глубже по истории; Directus и Strapi — с прошлых лет (в пилоте только 2026). Добавить продукты-API из плана:
  Kubernetes apiserver, GitLab (`api`), Supabase/PostgREST, Hasura, Kong; для пробелов — `grpc/grpc-*`,
  `grpc-gateway`, `graphql-js`, Apollo Server.
- **Не масштабировать:** NestJS, Express и их мелкие пакеты — оставить только инкрементальную докачку (наш стек,
  регресс-пруфы), с предфильтром по заголовку до LLM (`exclude_title` в `sources.yaml`). Калибровка на пилоте:
  отсекается 28 из 198 багов вне области у nest и express (≈ 14 %), ни одного API-бага; широкий список
  (provider, module, type) терял 5 API-багов, включая 2 `new`.
- **Промпт `triage_abstract.md`:**
  - разделить `other` на `framework-internal`, `usage` (ошибка настройки или использования), `insufficient-data`,
    `client-lib` (клиентские библиотеки, песочницы);
  - правило «проявляется после перезапуска или по истечении времени, но через API — это API»;
  - в `match` отдельное поле `variant` — шаг в повелительной форме, без «Добавить …». Сейчас вариант вырезается
    из заметки регулярным выражением, и около 70 шагов начинаются с «Добавить».
- **Ревью:** перед переводом `draft` → `approved` прогнать выборку точности; на следующей партии решения по
  кластерам делать человеком до применения, а не «принять всё».
